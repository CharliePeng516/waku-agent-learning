术语表

术语在第一次用到时加入，释义只求"能正确用在代码里"，不追求教科书式的完整。 （English version）

模块 1 — LLM API 基础

Token（词元）
LLM 实际读取和计费的最小单位——一段文本片段，英文里大约是四分之三个单词，不是字符，也不是完整单词。每次请求/响应都会报告 token 数量：这既是计费依据，也是占用上下文窗口的量。
Context window（上下文窗口）
模型单次调用能"看到"的最大 token 数（输入+输出合计，具体上限因厂商而异）。系统提示词、对话历史、工具 schema、检索到的文档——所有内容都在争抢这个预算。
System prompt（系统提示词）
随消息列表一起发送、但不属于消息列表本身的一条常驻指令，模型会把它当作最高优先级的框架，而不是对话中的一轮。Anthropic API 里是独立的 system 参数；OpenAI 的 chat 格式里则是数组开头一条 role: "system" 的消息——概念相同，线上格式不同。
Message（消息）
对话中的一轮：{"role": "user" | "assistant", "content": ...}。整个数组就是完整的对话状态——LLM API 本身是无状态的，调用方每次都要把完整历史重新发一遍。
Content block（内容块）
Anthropic 里消息 content 内部的最小单元：一个带类型的对象（text、tool_use、tool_result、image 等），而不是一段纯字符串。同一条助手回复里可以同时混有一个文本块和一个 tool_use 块。
Wire format（线上格式/协议格式）
某个厂商 API 实际要求/返回的具体 JSON 结构。Anthropic 和 OpenAI 对基本相同的概念用了两套不同的结构（见请求/响应速查表）——并不存在唯一的"LLM API 标准"，这也是为什么 waku/loop/models.py 里需要 OpenAICompatClient 这样一层适配器。
stop_reason / finish_reason
模型为什么停止生成：例如 end_turn（说完了）、tool_use（它想调用一个工具，正在等你执行）、max_tokens（被截断了——输出撞到上限）。Anthropic 把这个字段叫 stop_reason；OpenAI 叫 finish_reason。agent 循环正是靠判断这个值，来决定是回复用户，还是去执行一个工具。
Usage（用量）
响应里附带的 token 计费信息（Anthropic 格式里是 input_tokens / output_tokens）。这就是你这一次调用的实际账单，也是做成本或延迟预算的第一手输入。
