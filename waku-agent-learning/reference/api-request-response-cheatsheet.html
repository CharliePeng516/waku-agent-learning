Sending a tool result back

Both formats require you to append the tool's output as a new message before calling the API again — the model never runs anything itself, it only asks.

AnthropicOpenAI
a user message whose content is one or more {type: "tool_result", tool_use_id, content} blocks a message with role: "tool", tool_call_id, and content
Why this matters

There is no single "the" LLM API. Two shapes for the same four concepts (instructions, history, tools, token accounting) is what you get in 2026, and most other providers copy one of these two almost verbatim. waku/loop/models.py's OpenAICompatClient is a ~110-line adapter that translates OpenAI's shape into Anthropic's shape at the boundary, so the rest of the codebase — the loop, the tools, the tracing — only ever has to know one format. That's a real architecture decision you'll face the first time you support a second provider in any product.
