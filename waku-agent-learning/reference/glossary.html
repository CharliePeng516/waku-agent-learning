Module 1 — LLM API fundamentals

Token
The unit an LLM actually reads and bills in — a chunk of text, roughly ¾ of a word in English. Not a character, not a word. Every request/response reports token counts; that's what you're billed on and what fills the context window.
Context window
The maximum number of tokens (input + output combined, provider-dependent) a model can attend to in one call. Everything you send — system prompt, message history, tool schemas, retrieved documents — competes for this budget.
System prompt
A standing instruction sent alongside (not inside) the message list, read as top-priority framing rather than a turn in the conversation. In Anthropic's API it's a dedicated system parameter; in OpenAI's chat format it's a message with role: "system" at the start of the array — same idea, different wire shape.
Message
One turn in the conversation: {"role": "user" | "assistant", "content": ...}. The full array is the entire conversation state — LLM APIs are stateless per call, so the caller resends the whole history every time.
Content block
Anthropic's unit inside a message's content: a typed object (text, tool_use, tool_result, image, …) rather than a plain string. A single assistant turn can mix a text block and a tool_use block in one response.
Wire format
The specific JSON shape a provider's API expects/returns. Anthropic and OpenAI use two different shapes for essentially the same concepts (see the request/response cheat sheet) — there is no single "the" LLM API standard, which is why an adapter layer like waku/loop/models.py's OpenAICompatClient exists.
stop_reason / finish_reason
Why the model stopped generating: e.g. end_turn (done talking), tool_use (it wants to call a tool and is waiting on you), max_tokens (truncated — you hit the output cap). Anthropic calls the field stop_reason; OpenAI calls it finish_reason. Branching on this value is how an agent loop knows whether to reply to the human or run a tool.
Usage
The token accounting on a response (input_tokens / output_tokens in Anthropic's shape). This is your literal bill per call and the input to any cost or latency budgeting.
